\title{Executable Preconditions versus Text Similarity for Replaying Compiled Agent
Programs: A Pre-registered Test on Real Lock-file Merges}

\begin{abstract}
Agents that compile a solved task into a reusable program must decide, on each new task, whether
to replay one. A wrong replay, a \emph{mis-fire}, runs a program whose resolution is not
acceptable for the state at hand. We compare two ways of deciding: \emph{executable
preconditions}, shell probes that must all hold on the live state, and \emph{text similarity}
between the request and each program's description. The comparison is made at matched coverage,
because a dispatcher that never fires never mis-fires. On 400 labelled dispatch pairs built by our
own injectors for five git maintenance faults, precondition dispatch mis-fired on 0 of 563 fires
across three independently built libraries, while three local text scorers mis-fired on 71--90\%
of their fires. That result is graded by our own rules, and a decision tree that reads the state
without running any program matched it. We therefore pre-registered a test on states and labels
we did not make: 274 lock-file merges from 11 public repositories, labelled by what each
maintainer committed. The registered claim that precondition dispatch rarely mis-fires was
\emph{falsified}: it was wrong on 62 of 150, 10 of 122 and 132 of 244 fires in the three
libraries. It still mis-fired less than lexical similarity at matched coverage in every library,
but almost all of that margin came from merges without a conflict. On real conflicts every
dispatcher was almost always wrong, because maintainers regenerate or hand-edit lock files, and
the library's resolutions could express only 1 of 161 of them. An exploratory analysis suggests
that the one place where executing checks differs from reading the state is \emph{refusal}: two
of three libraries mostly declined conflicts that nothing could resolve, while a state reader with
the same scope fired on all of them. We release the benchmark, the data, independent verification
scripts and a pre-registered follow-up study that tests refusal directly.
\end{abstract}

\section{Introduction}

LLM agents increasingly reuse their own past work. A task solved once is compiled into a program
that can be replayed later without a model call
\cite{fikes1972macrops,cai2024latm,wang2023voyager,chen2026skilldroid,li2026preact,jaber2026auto}.
Replay is cheap, but it is only useful if the agent replays the right program. Most systems decide
by \emph{similarity}: they embed the request and retrieve the closest stored skill
\cite{wang2023voyager,chen2026skilldroid}. An older idea is to attach \emph{executable
preconditions} to each program and fire it only when they hold on the live state, as MACROPS did
for generalized robot plans in 1972 \cite{fikes1972macrops}.

The mechanism is not new, and neither is the argument that the most similar case is not always
the most reusable one \cite{smyth1998adaptation}. What we could not find is a head-to-head
measurement:

\begin{quote}
\emph{At matched dispatch coverage, does executable-precondition dispatch mis-fire less often
than text-similarity dispatch, where a mis-fire is a program that fires, claims it succeeded, and
did not?}
\end{quote}

Recent work brackets the question. A production executability gate prunes candidates after
semantic recall \cite{wix2026gating}, and a retrieval benchmark measures how often risky sibling
skills are exposed \cite{ding2026rightfamily}. Neither compares the two decision rules at matched
coverage.

This report makes three contributions.

\begin{enumerate}
  \item \textbf{A benchmark and apparatus} for dispatch-level comparison. It covers branchy git
  maintenance faults, programs compiled by an LLM from solved episodes, two-sided admission, and a
  mismatch-versus-coverage metric (Section~\ref{sec:method}).
  \item \textbf{A result on our own states that does not transfer.} On states built and labelled
  by our own code, precondition dispatch never mis-fired, but a state-reading classifier matched it
  (Section~\ref{sec:synthetic}). On real merges, under a study registered before its data was mined,
  the claim that precondition dispatch rarely mis-fires was falsified (Section~\ref{sec:real}).
  \item \textbf{A narrower, testable hypothesis.} Exploratory analysis locates the remaining
  difference in refusal, and we pre-registered a study over a population of builds to test it
  (Section~\ref{sec:study2}).
\end{enumerate}

We report the negative result in full because it is the most informative one. The near-zero
mis-fire rate on our own states said more about our labels than about the mechanism.

\section{Related work}
\label{sec:related}

\paragraph{Compile once, replay cheaply.}
LATM has a strong model build reusable tools that a cheaper model then calls \cite{cai2024latm}.
Voyager stores executable skills and retrieves them by embedding similarity
\cite{wang2023voyager}. SkillDroid compiles mobile GUI trajectories into parameterized templates,
replays them with no LLM call and routes new instructions through a matching cascade
\cite{chen2026skilldroid}. PreAct compiles a computer-use trace into a state-machine program that
checks the screen before each action \cite{li2026preact}. Auto compiles deterministic spans of
agent behaviour into sandboxed programs behind calibrated guards, and reports that a loose guard
silently mislabels many answers \cite{jaber2026auto}. These systems establish that replay can be
cheap. They do not compare how the replay decision is made.

\paragraph{Precondition-based dispatch.}
MACROPS dispatches a cached plan by testing precondition kernels against the current state, and
replans when they fail \cite{fikes1972macrops}. Soar's chunking re-fires compiled rules whose
conditions match \cite{laird1986chunking}. In reinforcement learning, an option's initiation set
plays a similar role \cite{sutton1999options}. Smyth and Keane argue that similarity is a poor proxy
for adaptability in case-based reasoning \cite{smyth1998adaptation}.

\paragraph{Gating and retrieval risk.}
A deterministic executability gate deployed in a customer-care agent removes skills whose hard exit
conditions hold, after semantic recall \cite{wix2026gating}. It can prune a candidate but never
rescue one that recall missed. A benchmark of same-family skill retrieval measures the exposure of
risky siblings in the top results \cite{ding2026rightfamily}. That is exposure, not execution.

\section{Method}
\label{sec:method}

\subsection{Task family}

Tasks are branchy maintenance faults injected into disposable git sandboxes. A fault is admitted
only if it recurs, can be checked without a model, and has more than one correct resolution
depending on the state. Five are git faults: \code{dirty\_tree}, \code{diverged},
\code{submodule\_moved}, \code{branch\_renamed} and \code{lockfile\_conflict}. A sixth,
\code{config\_renamed}, changes files rather than history. Each fault has an \emph{intent} with a
set of named resolutions, for example \code{take\_upstream} or \code{keep\_local} for a lock-file
conflict. A rule over the observed state says which resolutions are acceptable.

\subsection{Programs and admission}

An LLM agent solves an episode in a sandbox, and the solved trace is compiled into a program with
three parts: parameters, \emph{preconditions} (shell probes, all of which must hold for the program
to fire) and postconditions. A program is admitted to the library only through a
\emph{two-sided} gate. It must reach its postconditions on a freshly faulted sandbox, and its
preconditions must \emph{reject} negative sandboxes, states where firing would be wrong. A
precondition set that accepts everything is a defect. Each library is built once from a fixed
plan of episodes, the admit set, and then frozen. Dispatch never writes to it.

\subsection{Dispatchers}

\begin{itemize}
  \item \textbf{Precondition dispatch (arm 3).} It evaluates each program's probes on the state and
  fires the first program whose preconditions all hold. It makes no model call and has no score,
  so it is a single operating point.
  \item \textbf{Text similarity (arm 2).} It scores each program's description against the request
  text. Three scorers are used: a lexical scorer, a pinned bi-encoder
  (\code{all-MiniLM-L6-v2} \cite{reimers2019sbert}) and a pinned cross-encoder reranker
  (\code{ms-marco-MiniLM-L-12-v2}). The reranker was the strongest of 13 local models screened
  for their ability to rank the right program first. Arm 2 sweeps a threshold, and it is read at
  arm 3's coverage.
  \item \textbf{State-reading control.} One decision tree per intent over generic features of the
  observed state (every field, pairwise overlaps and equalities, none naming a rule). It is fitted
  on the 56 states the libraries were built from. It makes no model call and runs no compiled
  program.
\end{itemize}

\subsection{Metric}

The primary metric is \emph{mismatch at matched coverage}. Coverage is the share of pairs on which
a dispatcher fires. Mismatch is the share of its fires whose resolution is not in the pair's
acceptable set. Mismatch is scored separately from episode success: a wrong program can fail its
postconditions, fall back to the agent, and still end the episode successfully. Matching on
coverage matters because a dispatcher that fires on nothing has a perfect mismatch rate. Intervals
are 95\% Wilson intervals \cite{wilson1927} for rates. On real merges, differences get 95\%
bootstrap intervals with cases clustered by repository.

\subsection{Request text}

Requests are drawn from an \emph{uninformed} channel that never consults the state, so the text
carries no information about which resolution is right. A bag-of-words classifier trained on these
requests has an AUC of exactly 0.5 on every intent, by construction. The test that pins this
guards against the sampler starting to consult the state. It does not certify the wording.

\section{Results on the project's own states}
\label{sec:synthetic}

\paragraph{Setup.}
Three replicate libraries were each built from the admit set with a commercial LLM
(\code{deepseek-flash}, temperature 0). They admitted 13, 14 and 13 programs. Each was scored on
400 labelled pairs from evaluation seeds no build used: 40 per fault for five git faults, plus a
fault-free negative for each. No model call is made after the build.

\paragraph{Result.}
Table~\ref{tab:synthetic} shows the result. Precondition dispatch mis-fired on none of its 563
fires. The text scorers mis-fired on 71--90\% of theirs at the same coverage, a gap about five
times the smallest difference the pair count could detect. Swapping the lexical scorer for the
bi-encoder or the reranker narrowed the gap by less than 0.1 in every replicate.

\paragraph{Why this is not the result.}
Every pair's acceptable set is a rule over the observed state, and the rule is ours. The
state-reading control fired on 190 of the 400 pairs with none wrong. On 200 held-out pairs it was
also never wrong, where precondition dispatch had 8--21 mis-fires. So the table supports a weaker
claim: a dispatcher that reads the state beats one that does not, and compiled preconditions are
one such dispatcher.

\paragraph{Held-out states.}
On 40 seeds no build drew, with new paths, names and history shapes, four of five sources
carried: 1 mis-fire in 480 fires. The lock-file source did not: 41 of 101 fires were wrong, all on
paths containing a space or a non-ASCII character. Five learned probes read git's path lists
without \code{-z}. Each was an absence check, so on a quoted path it found nothing, passed, and
the program fired. Admission had passed them because no shipped state needed quoting.

\section{A pre-registered test on real lock-file merges}
\label{sec:real}

\subsection{Registration}

Before any case was mined, we committed a registration document whose SHA-256 is pinned in the
code. The measurement refuses to run unless the document is present, committed and unchanged. It
fixes the hypotheses, the ordered list of repositories, the case and label definitions, the
analysis and the decision rules. A pilot stage on 44 merges motivated one amendment, which was
committed before the confirmatory data was mined. The pilot tests nothing.

\paragraph{Hypotheses and rules.}
Rule 2 holds that precondition dispatch rarely mis-fires: the Wilson lower bound of its mismatch is
at most 0.10. H1: at matched coverage it mis-fires less than lexical similarity. H2: it mis-fires
less than the state-reading control. H3, added by the amendment: it fires less often than the
control on conflicts that no resolution can express.

\subsection{Cases and labels}

A \emph{conflicted case} is a two-parent merge commit whose sides both changed a lock file and
where \code{git merge-tree} reports a conflict in it. A \emph{clean case} changed a lock file on
both sides and merged cleanly. Each case's state is rebuilt from the parents and merge base. The
label is what the maintainer committed. A resolution is acceptable on a conflicted case if it
reproduces the maintainer's lock file, and \code{merge} is acceptable on a clean case whose tree
equals the committed tree. The dispatchers decide read-only, with no model call, using the three
frozen libraries of Section~\ref{sec:synthetic}.

Sixteen of 18 listed repositories were mined, in the registered order, until the target was met.
Five yielded no case. The confirmatory set has 274 cases from 11 repositories: 161 conflicted and
113 clean. No repository exceeds the registered cap of 25\% of the target.

\paragraph{Decisions, as registered.}
Table~\ref{tab:real} gives the figures. Rule 2 is \textbf{falsified}: the lower bound of
precondition dispatch's mismatch is 0.338 and 0.478 in two of three libraries. H1, H2 and H3 are
supported in every library.

\paragraph{Where the margins come from.}
Almost no conflict is expressible. Maintainers regenerated the lock file on 79 of the 161
conflicts, did something else on 48, took the local side on 20 and upstream's on 12. The intent's
line-union resolutions reproduce only 1 of the 161. Precondition dispatch's right fires are
\code{merge} on clean merges, fired from another intent's programs, which the registration counts
as right. The registered control decides with the lock-file intent's own tree, so it can never
fire \code{merge}. H2 therefore compares fires on mostly clean cases with fires on conflicted
ones, and wherever both dispatchers fired, both were wrong (McNemar discordant pairs 0/0 in every
library). We read H2 as a flaw in the registered control's scope, not as evidence for executing
preconditions. We should have seen it when registering.

\subsection{Exploratory: a control with the same scope}

After seeing the data, we gave the control arm 3's scope: it fires the most probable resolution
of any intent's tree. This analysis is labelled exploratory and tests nothing. The rescoped
control was right on 110 of 112 clean merges it fired on, as often as precondition dispatch. It
fired on all 161 conflicts and was right on none. Its \code{merge} comes from a tree whose rule
refuses a conflicting sync, but only 4 of its 56 training states conflict, so it never learned to
refuse. The compiled \code{merge} programs instead run a probe that tries the merge and refuse
when it conflicts. In this data, refusal is the one place where executing a check differed from
reading the state. Even that differed across libraries: they fired on 22.5\%, 5.6\% and 81.9\%
of the 160 inexpressible conflicts.

\subsection{Verification}

A script that imports nothing from the project recomputes every count, matched point, point
estimate and rule-2 bound from the released files, exactly. With its own random seed, its
bootstrap intervals land within 0.01 of the registered ones. A second script re-fetched five
repositories (55 cases, 20\%) at their pinned tips and re-derived every label from git alone: the
merge base, the conflict, and the acceptable set. All 55 agree.

\section{Are the graders right?}
\label{sec:graders}

Every figure above depends on graders written in this project. We mutation-tested them
\cite{jia2011mutation}, flipping comparisons, swapping \code{and}/\code{or}, removing \code{not},
swapping booleans and moving integers by one. That produced 171 mutants. 133 were killed and 30
change only a verdict's message. Of the 8 survivors that could change a verdict, 5 marked failure
clauses that no test exercised. Each now has a test that kills it, and the other 3 are
equivalent. The score as run was 0.943. None of the five clauses was reached by a state the
benchmark builds, so no reported figure was graded by a broken clause. Property-based tests
\cite{maciver2019hypothesis} check two graders on 300 generated states each, with no failure.
Agreement with human judges has not been measured.

\section{Threats to validity}

\begin{itemize}
  \item \textbf{Construct.} Mis-fire is judged against an acceptable set. On real merges, a
  resolution that differs from the maintainer's commit counts as wrong even if it would build. The
  external oracles (the ecosystem's lock-file tools, the projects' own tests) are not built.
  \item \textbf{Internal.} The libraries come from one LLM at temperature 0, three builds. They
  differ widely in behaviour, so three builds do not describe the population of builds. The
  registered control's scope was a design flaw (Section~\ref{sec:real}).
  \item \textbf{External.} One family of faults, git maintenance, and on real data only lock-file
  merges from 11 repositories. Nothing here is measured at episode level: cost, the misses an agent
  would then solve, and online learning were not run at scale.
  \item \textbf{Text scorers.} Only local scorers were compared. An LLM judge that reads the state
  is implemented and registered but has not been run.
  \item \textbf{Author.} One author built the apparatus, wrote the graders and ran the analyses.
  The pre-registration, the independent recomputation and the mutation tests are partial
  mitigations, not independent review.
\end{itemize}

\section{A registered follow-up: refusal over a population of builds}
\label{sec:study2}

The exploratory finding is a hypothesis, not a result. We have registered a second study before
any of its data exists, with its document pinned by SHA-256 like the first. It treats builds as a
population: 10 builds in each of two admission configurations, each build permuting the order of
the admit-set plan with its own seed. Configuration~R also admits a program only if its
preconditions refuse every state in a frozen set of up to 40 real inexpressible conflicts from four
admission repositories. The primary hypothesis compares configuration~R with a state reader trained
on the same refusal states, so both sides get the same evidence. Evaluation cases come from 12
repositories no earlier stage has touched, and are mined only after all 20 libraries are frozen.
Intervals come from a two-level bootstrap over repositories and builds. The study states its
detectable effect, about 0.3 in fire rate, and its stopping and underpowered rules in advance.

\section{Conclusion}

On states we built and labelled, executable-precondition dispatch never mis-fired, but neither did
a classifier that only reads the state. On real lock-file merges, graded by what maintainers
committed, the claim that it rarely mis-fires was falsified. What survived is narrow: it fires
\code{merge} on clean merges where text similarity does not, and some libraries refuse conflicts
that nothing can resolve. The broader lesson is about evaluation. A near-zero error rate measured
against one's own labels says little until the same dispatcher faces states and labels someone
else made.
